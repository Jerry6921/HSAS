## 1. 接手摘要

用户希望把 HIQS 打造成能满足各类 HKU 相关需求的 Agent Skill Set，先服务自己，再推广给其他 HKU 学生。首个用例是根据 ENGG1000 的 lecture、past papers 和 quizzes 生成用于学习与复习的分段课程笔记。第二个用例是根据用户要求与 syllabus 查询 SIS 课程信息，规划课程与课表，并结合自动 enrol，在失败后重新规划和执行。

用户已选择 **B：一次生成整套，内部按学习单元分段**。内部可以分批处理，但正常执行不以用户逐段回复“继续”为前提。

第二用例已确认两项边界：**只在事先认可的候选池内换课、换班或换时段；固定已成功 enrol 的课程，只调整尚未成功的目标。** 完整需求见[第二用例交付文档](hiqs-course-planning-enrolment-handoff.md)。

接手后的第一步：阅读本文件、对应的用例文档、仓库 Agent 说明及现有 Skills，重新核对当前能力与目标差距，形成最小架构方案。已有课程笔记相关实现应先检查并复用；自动 enrol 需单独核验真实状态与执行合同。当前交付没有选定第二用例的最终接口或存储模型，不应直接按假定的架构开始大范围重构。

本文件中的状态标签：

- **U：用户明确决定**，来自本轮对话，可作为产品约束。
- **D：必要推导**，为完成已确认任务而推导出的行为，需在设计和实现报告中说明。
- **P：设计建议**，供架构评估，尚未成为用户确认的具体方案。
- **E：现状证据**，来自当前本地文件检查；代码存在与运行验收是不同状态。

## 3. 产品范围

### 3.1 当前可推进的首个能力

从指定课程的授权资料出发，完成资料盘点、课程结构组织、学习笔记生成、考题关联、复习支持和成果核验。ENGG1000 是首个验证课程；课程代码不应成为核心流程的硬编码条件。

建议工作名称：`hiqs-course-notes`（P-01）。名称、Skill 拆分数量及安装位置仍由后续设计决定。

### 3.2 长期候选范围

对话曾提出课程与学业、学习与研究、校园生活、行政事务、机会与发展等候选方向。这些是 Agent 的能力地图建议，尚无已确认的完整用例、优先级或执行合同。本轮不把这些候选方向展开为待实现的模块。

### 3.3 当前未要求的扩展

本轮未要求独立聊天应用、全面 UI 改版、多用户云平台、自动提交作业、代发邮件、自动预约或全校网站采集。学习笔记生成任务也不等于向 canonical 课程数据库添加新的课程事实。

### 3.4 第二个明确能力：课程规划、排课与自动 enrol

将 SIS 课程资料与 syllabus、用户要求、实际班别和 enrol 状态结合，生成方案并执行；失败后保留成功课程，在认可候选池内重新求解剩余目标。此能力已进入明确需求范围，不再仅列为“课程与学业”的长期候选方向。

专门的流程、官方依据、执行边界、状态和 14 项验收场景由[第二用例交付文档](hiqs-course-planning-enrolment-handoff.md)维护，本文件不复制完整细则。

## 4. 首个用例：一次生成整套课程笔记

### 4.1 输入与范围解析

自然语言入口：

> 帮我根据 ENGG1000 的 lecture 和 past paper／quiz 生成分段课程笔记，用于学习与复习，一次生成整套。

执行时需解析：课程身份、当前学期或明确指定的资料范围、讲义版本、可访问的历年试题与 quizzes，以及可用答案。当前尚未实际读取 ENGG1000 的完整资料，文档不声称资料已齐全，也不预先指定该课程的实际章节目录。

能够从已验证信息确定的内容直接使用。存在多个学期或多个课程身份且会改变输出范围时，提出一个聚焦问题；这类范围问题与“每段生成前要求继续”是不同情形。

### 4.2 资料职责

| 资料 | 在任务中的作用 | 处理原则 |
| --- | --- | --- |
| 当前 lecture／syllabus／课程说明 | 确定范围、术语、符号、课程顺序及学习目标。 | 读取相关完整内容，包括对理解有影响的图表、例题和注释。 |
| Past papers／quizzes | 识别考查方式、问题结构、常见误区，并关联学习单元。 | 保留可确认的年份、版本、题号；历史题不自动代表当前课程范围。 |
| 官方答案／marking scheme | 核对解法与可见评分要求。 | 与 Agent 自行推导的答案分开标注；没有评分方案时不编造官方评分点。 |
| 教学补充 | 补足讲义中的解释跳步、必要背景和迁移练习。 | 标明为补充；外部事实提供可核对来源，构造例题说明其性质。 |

Lecture 与试题的关系是“课程覆盖 + 考查分析”。某概念没有出现在已取得的试题中，不构成删除该概念的依据；旧试题涉及当前讲义未涵盖的内容时，应标明差异，避免无说明地扩大当前课程范围。

### 4.3 建议交付组成

以下是实现 U-03 至 U-05 的建议交付组织（P-02）。学习与复习两种用途以及整套分段交付已确认；是否分成独立页面或文件仍可调整。

| 组成 | 内容 | 可观察结果 |
| --- | --- | --- |
| 课程总览 | 范围、先修知识、单元次序和导航。 | 用户能理解整套笔记的学习顺序。 |
| 分段学习笔记 | 按完整概念或问题结构组织的详细内容。 | 各段可独立定位，跨段术语与前提保持连续。 |
| 试题对应表 | 题目与单元、概念、题型及相关来源的关联。 | 用户能从题目回到解释，也能从单元找到相关题目。 |
| 复习材料 | 关键概念、公式及条件、题型识别、区别与练习。 | 用户能够快速复习；详细解释仍可通过链接找到。 |

## 5. 功能与质量要求

### F-01：建立资料清单（D）

开始生成前，建立本次输入清单，保留课程、资料身份、角色、来源、版本或内容哈希（能够取得时）、可读状态和范围决定。识别重复文件，保留必要来源关系。无法确认年份或角色的资料明确标注，不根据文件名猜成确定事实。

### F-02：完成范围内的资料阅读（D）

不能把一次检索返回的少量相关片段当成整门课程的完整输入。使用材料清单规划覆盖，再完整读取各单元所需的来源。扫描页、图示、表格或公式的文本提取不完整时，按实际需要查看原始视觉内容或使用 OCR，并保留识别限制。

### F-03：按知识结构分段（D）

围绕概念、必要前提及问题结构安排学习单元，保留与 lecture 顺序和页码的对应关系。分段应让内容可以系统学习，不依赖固定字数、固定页数或每个文件机械生成一段。调整来源顺序时说明教学上的理由。

### F-04：整套执行与交付（U-05、D）

在输入范围和必要目标已确定后，连续完成授权范围内的全部单元，并提供统一入口或清楚的成果清单。允许内部批次、分文件输出和保存检查点，正常执行不要求用户逐段发送“继续”。

运行中断时，保留已完成成果并准确报告剩余范围。重试应能识别已完成部分，避免无说明地重复生成或宣称任务仍在后台运行。完成、部分完成和阻塞状态需要可区分；后台调度平台不是当前确定的实现要求。

### F-05：学习内容可独立使用（D；教学细则为 P）

笔记应补足 terse slides 中影响理解的必要环节，保持定义、符号、假设及前提的一致性。建议复用现有课程笔记 Skills 的教学规范：先说明概念解决的问题，再建立直觉与形式表达；推导交代关键步骤；用结构不同的例子揭示共同机制；解释适用条件与有实质意义的误区。

公式密集内容应说明符号、单位、方向与适用条件。跨学科复用时按学科调整结构，避免把所有课程强行套进工程计算模板。

### F-06：关联试题且保持答案来源（D）

把范围内试题关联到对应单元与概念；无法匹配的题目进入明确列表。区分官方答案、Agent 推导、教学变式以及尚未确定的解答。题目出现频次只描述已分析样本，不作为未来考试出现概率或保证。

### F-07：同时支持复习（U-04、D）

提供可以快速定位概念、方法与条件的复习支持，并能回到详细解释。独立 rapid-review 页面或文件是建议组织方式；公式表只纳入当前范围中有依据的公式和实际使用的补充内容。定性课程按概念、论证与证据组织。

### F-08：来源与覆盖可核对（D）

使用真实可定位的文件、页码／slide、题号或其他来源标识。无页码资料使用可确认的章节、标题或节点，不伪造定位。覆盖检查需把输入范围与输出逐项对照；来源阅读完成、笔记已生成与学生已经掌握分别记录。

### F-09：后续可定位修订（P）

建议支持“修改某一段”“补讲此概念”“加入新 quiz”并更新受影响内容、试题关联及复习材料。保留用户修改，避免无说明地重建整套笔记。首版是否纳入完整增量更新，由架构方案说明取舍；整套首轮交付仍是优先目标。

### F-10：成果保存与发布可验证（D）

根据已确定的目标保存完整成果，读取保存结果并检查导航、关键段落、公式和来源是否保留。分别报告内容生成与发布结果。目标服务失败时，保留可恢复成果并报告发布未完成；不能用对话中的成功描述替代实际保存。

## 7. 架构设计需要回答的问题

以下是设计工作要求，具体答案尚未确认：

1. **发现与路由**：如何让 HKU 请求进入正确能力，保持每个 Skill 的触发范围清楚；是否需要总入口，需依据真实用例决定。
2. **资料与生成边界**：复用哪些现有 MCP 工具，完整课程阅读和视觉内容处理还缺哪些能力；避免重复实现现有查询及校验规则。
3. **成果与状态归属**：笔记正文、来源清单、覆盖记录、任务进度和用户修改分别保存在哪里；哪些是可重建派生数据，哪些需保留历史。
4. **批次与恢复**：怎样在宿主实际运行限制内完成整套任务，并在中断后恢复；无需用户逐段继续不等于必须增加常驻后台服务。
5. **发布合同**：本地文件与 Notion 等目标如何选择、核对和报告；复用课程投影能力前应检查其语义是否适合笔记。
6. **迁移与分发**：如何扩展当前课程中心定位，同时保持现有课程同步、信息查询及校验写入可用；怎样把个人配置与共享技能分离。

建议原则（P-03）：Skills 承担领域操作方法与工具编排，确定性工具承担可靠执行；按需要加载说明；共享来源与检索能力，各领域保留适当的数据模型。该原则不预设最终目录结构、Skill 数量或工具命名。

现有项目约束继续适用：课程事实通过既有验证与 apply 流程更新；来源内容作为数据处理；账户凭据保留在用户认证边界；MCP、CLI 和 UI 通过既有应用边界工作。扩大产品范围不自动改变这些约束。

## 9. 验收场景草案

以下场景是从 U 与 D 推导出的拟议验收，P 类能力单独标明。验收需检查实际输入与保存成果，不能只匹配输出措辞。

| ID | 场景 | 可检查结果 |
| --- | --- | --- |
| AC-01 | 范围内 lecture 和试题均可读取。 | 一次请求交付所有已规划单元的完整内容和学习／复习入口，无逐段“继续”要求。 |
| AC-02 | 大量内容需要多个内部批次。 | 最终导航连贯，符号与前提一致；后半部分没有因运行或篇幅限制静默省略。 |
| AC-03 | 试题没有考到某个 lecture 主要概念。 | 该概念仍有学习覆盖，试题缺席不会自动变成不在范围。 |
| AC-04 | 历年题涉及当前讲义未覆盖的主题，或没有官方答案。 | 标明范围差异；解答来源可辨，未编造官方答案或评分点。 |
| AC-05 | 某扫描页／图表无法可靠读取。 | 精确列出失败位置与受影响内容；读取成功的部分可交付，整体状态准确。 |
| AC-06 | 存在同课程不同学期或其他课程的相似文件。 | 使用已解析范围；关键歧义得到解决，未混用课程、版本或发布目标。 |
| AC-07 | 执行或发布途中失败。 | 已保存内容仍可定位；完成与剩余范围可核对，发布状态准确，不产生无说明的重复成果。 |
| AC-08 | 用户尚未学习生成的笔记。 | 系统只声称笔记完成，不把生成记录当作已掌握的证据。 |
| AC-09 | 使用另一门课程执行同类任务。 | 复用流程，切换来源、符号与目标；核心实现无 ENGG1000 或个人身份硬编码。 |
| AC-10 | 用户加入新 quiz 或修改某段（P/F-09）。 | 若首版采纳此能力，能定位受影响内容并保留无关正文与用户修改。 |

ENGG1000 的实际单元数、题目数和资料覆盖比例应在执行后依据清单报告。当前不填入历史统计作为本次验收基线。
